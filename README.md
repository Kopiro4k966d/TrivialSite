Сайт, API авторизации, лицензии, профиль, админ-панель и защищённая загрузка лаунчера.

## Локальный запуск

1. Установите Node.js 20+ и PostgreSQL.
2. Скопируйте `.env.example` в `.env`.
3. Заполните `DATABASE_URL` и длинный случайный `SESSION_SECRET`.
4. Выполните:

```bash
npm install
npm run migrate
npm start
```

5. Откройте `http://localhost:3000`.

`AUTO_MIGRATE=true` позволяет API самостоятельно применить ту же миграцию при первом запросе. Команда `npm run migrate` удобнее для явной проверки перед запуском.

## Развёртывание на Vercel

В настройках проекта добавьте переменные:

```text
DATABASE_URL=postgresql://...
SESSION_SECRET=<длинная случайная строка>
AUTO_MIGRATE=true
DATABASE_SSL=true
DATABASE_POOL_SIZE=1
ALLOWED_ORIGINS=https://trivialclient.vercel.app
```

После redeploy проверьте:

- `/api/health` — поле `databaseConfigured` должно быть `true`;
- `/api/status` — должен вернуться ответ с `database: "ok"` и `schema: "ok"`.

Если автоматические DDL-запросы запрещены провайдером БД, выполните `database/schema.sql` в SQL Editor и установите `AUTO_MIGRATE=false`.

## Назначение администратора

```sql
UPDATE users
SET role='admin'
WHERE LOWER(username)=LOWER('your_username');
```

Допустимые роли для создания ключей: `creator` и `admin`.

## Проверка ключей

1. Войдите администратором и откройте `admin-panel.html`.
2. Создайте ключ. Новый формат: `TRIV-XXXX-XXXX-XXXX-30D`.
3. Войдите обычным пользователем и активируйте ключ в профиле.
4. Повторная активация того же ключа должна вернуть сообщение, что ключ уже использован.

Старые ключи продолжают приниматься, если они есть в таблице `licenses`.

## Публикация клиента

Задайте в окружении:

- `CLIENT_DOWNLOAD_URL` — HTTPS URL загрузки JAR;
- `CLIENT_SHA256` — SHA-256 JAR;
- `MINECRAFT_VERSION` и `FABRIC_LOADER_VERSION`.

Без `CLIENT_DOWNLOAD_URL` лаунчер авторизуется и показывает профиль, но запуск клиента блокируется.

## Защищённая загрузка лаунчера

По умолчанию используется `storage/launcher/TrivialLauncher.zip`. Прямой `/storage` закрыт, загрузка идёт через `/api/download/launcher` после проверки аккаунта и активной подписки. Вместо файла можно задать `LAUNCHER_DOWNLOAD_URL`.

## Платежи

Платёжные ссылки остаются внешними. Автоматическую выдачу ключей после оплаты необходимо подключать webhook-ом конкретного платёжного провайдера и обязательно проверять подпись webhook-а на сервере.
